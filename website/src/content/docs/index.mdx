## AI systems need governed context, not larger prompt dumps

Applications can already connect models to files, databases, tools and APIs. The unsolved problem is deciding which information is necessary, authorized, fresh, safe and appropriate for a particular operation.

**Context Governance Protocol (CGP)** moves that decision into a portable, model-agnostic context layer.

<div class="cgp-flow">Application / Agent
        │

        │

Privacy · Plan · Route · Policy receipts</div>

<CardGrid>
  <Card title="Context Contract" icon="document">
    Declare intent, token and byte budgets, freshness, provenance, privacy, purpose and jurisdiction as machine-readable constraints.
  </Card>
  <Card title="Local privacy" icon="shield-check">
    Extract and sanitize documents before external inference. Unsupported or insufficiently inspected inputs can fail closed.
  </Card>
  <Card title="Context planning" icon="rocket">
    Return a ranked Context Plan instead of transmitting every available document or retrieval result.
  </Card>
  <Card title="Portable evidence" icon="open-book">
    Generate receipts that explain which content, policy, model and route produced a decision without exposing original secrets.
  </Card>
  <Card title="Trust enforcement" icon="lock">
    Keep untrusted documents and tool results from promoting themselves into executable instructions or permissions.
  </Card>
  <Card title="EU governance direction" icon="approve-check">
    Compile declared use cases and policy packs into predictable runtime actions and evidence gaps.
  </Card>
</CardGrid>

The application should not need to implement a different compliance, privacy and routing pipeline for every model provider.

## CGP and MCP solve different layers

| Question | MCP | CGP |
|---|---|---|
| What tools and resources are available? | Primary concern | Can consume MCP resources |
| What is the minimum sufficient context? | Host responsibility | Protocol-level planning target |
| Must the document be sanitized locally? | Not a core concern | First-class privacy policy |
| Is this use compatible with purpose and jurisdiction? | Application responsibility | Governance target |
| Can the decision be reconstructed later? | Implementation-specific | Portable receipt model |

<Aside type="caution" title="Pre-alpha and not legal certification">
The reference implementation includes the core protocol and local privacy gateway. Provider routing, trust-firewall enforcement and EU policy compilation remain roadmap work. CGP is designed to accelerate governance and evidence collection; it cannot by itself certify legal compliance.
</Aside>
